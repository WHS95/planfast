# PlanFast QA 테스트 시나리오

이 문서는 PlanFast의 모든 기능에 대한 수동 QA 체크리스트입니다. 우선순위: **P0**(핵심 흐름, 매 릴리스 필수) · **P1**(주요 기능) · **P2**(엣지 케이스).

테스트 계정: 로컬 단일 사용자, 별도 로그인 없음. 사전 준비: `pnpm dev -p 3456` 실행 중, Claude 구독 로그인 완료(설정 → AI 항목 참고).

---

## 1. 홈 · 프로젝트 관리

| ID | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| HOME-01 (P0) | AI 질문으로 프로젝트 생성 | 홈 → "AI 질문으로 시작" 선택 → 아이디어 1~2문장 입력 → ⌘+Enter | 새 프로젝트 생성, `/p/<id>/prd`로 이동, 매니가 명확화 질문 5개 내외를 먼저 던짐 |
| HOME-02 (P1) | 파일 첨부로 시작 | "내 자료로 시작" 선택 → PDF/DOCX/TXT 1~3개 첨부 → 보충 설명 입력 → 전송 | 첨부 텍스트가 추출되어 매니가 PRD 초안 제안으로 응답 |
| HOME-03 (P2) | 파일 10개 초과 첨부 | 11개 파일 첨부 시도 | 10개로 자동 제한, 초과분은 무시(에러 없이) |
| HOME-04 (P1) | 즐겨찾기 | 프로젝트 카드 ⭐ 클릭 → 즐겨찾기 탭 확인 | 즐겨찾기 목록에 즉시 반영 |
| HOME-05 (P1)(회귀) | 프로젝트 복제 | ⋯ 메뉴 → 복제 → 복제본에서 AI 제안 표시 배지와 유저플로우 프레임 확인 | 이름에 "(복사본)" 붙은 새 프로젝트 생성, PRD/항목 내용 동일, **AI 제안 여부(aiProposed)와 유저플로우 프레임 구성도 함께 복제됨**(2026-09-05 수정: 이전엔 두 필드가 누락되어 복제본에서 초기화됐음) |
| HOME-06 (P0) | 휴지통 이동·복구·영구삭제 | 삭제 → 휴지통에서 확인 → 복구 → 목록 복귀 확인 → 다시 삭제 → 영구 삭제 확인(재확인 다이얼로그) | 각 단계 목록에 정확히 반영, 영구 삭제 후 DB에서 완전히 제거(재조회 404) |
| HOME-07 (P2) | Starter 플랜 프로젝트 3개 제한 | 해당 없음(로컬은 제한 없음) — 문서에 명시된 제한이 로컬 버전에는 적용되지 않음을 확인만 | 4개 이상 생성 가능해야 함(의도된 동작) |

## 2. PRD 에디터

| ID | 시나리오 | 절차 | 기대 결과 |
|---|---|---|---|
| PRD-01 (P0) | 필드 직접 편집 + 자동 저장 | 아무 필드나 클릭 → 텍스트 입력 → 다른 곳 클릭 | "저장 중…" → "저장됨" 표시, 새로고침 후에도 값 유지 |
| PRD-02 (P0) | **매니로 전체 작성 → 모두 반영 (회귀)** | "매니로 전체 작성" 클릭 → 완료 대기 → "모두 반영 (N)" 클릭 | **N개 필드 전부** 저장됨 (과거 마지막 1개만 저장되던 stale-state 버그 회귀 테스트 — 반드시 N=14 전후 필드로 확인) |
| PRD-03 (P1) | 섹션 단위 AI 보완 | 특정 섹션의 ✏️(AI 작성) 클릭 | 해당 섹션 필드만 제안 생성, 다른 섹션 값 불변 |
| PRD-04 (P1) | 제안 개별 반영/거절 | 제안 카드에서 "반영" 1개, "거절" 1개 클릭 | 반영한 것만 필드에 저장, 거절한 것은 원래 값 유지 |
| PRD-05 (P1) | 속성(칩) 필드 | 카테고리/역할/기기 입력 후 Enter, X로 삭제 | 칩 추가/삭제 정상, `values` 배열로 저장 |
| PRD-06 (P2) | 항목/섹션 추가·삭제 | "+항목 추가", "+섹션 추가", 커스텀 섹션 삭제 | 즉시 반영, 기본 5개 섹션은 삭제 버튼 없음(커스텀만 삭제 가능) |
| PRD-07 (P1) | 매니에게 섹션 질문 | 섹션 헤더의 💬 클릭 | 우측 매니 패널에 해당 섹션이 멘션으로 붙어 채팅 포커스 이동 |

| FEAT-08 (P1) | 슬롯 숨기기 | 특정 슬롯 숨김 처리 | 해당 슬롯 드로어에서 숨겨짐, 데이터는 유지(다시 보이기 가능) |

| FEAT-10 (P1) | 항목 삭제 시 하위 전체 삭제 | 요구사항 삭제 | 하위 기능·상세기능 전부 함께 삭제 |

- P0 항목은 매 기능 변경 후 반드시 재확인.

- 크로스 커팅 섹션(16)은 버그가 아니라 **현재 아키텍처의 의도된 경계**이므로, 실패가 아니라 "사용자에게 안내가 필요한 지점"으로 다룰 것.
